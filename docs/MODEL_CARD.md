## Intended use

**Primary intended use.** Demonstration of an end-to-end ML pipeline for Dutch foundation
subsidence risk scoring, including SHAP-based per-prediction explanations. The model
illustrates what such a system would look like with real labels and real feature data.

**Primary intended users.** Portfolio reviewers, ML engineers evaluating the pipeline
architecture, and domain experts interested in geospatial risk modelling for Dutch housing.

**Out-of-scope uses.** This model must **not** be used to:

- Inform actual property purchase, mortgage, sale, or insurance decisions
- Communicate risk status to property owners, tenants, or municipalities
- Serve as input to any regulated decision-making process
- Replace inspection by a qualified structural engineer (*funderingsadviseur*)

The labels are synthetic, 8 of 11 features are fully simulated (`soil_type` is hybrid:
29.5% BRO Bodemkaart, 70.5% coordinate rule), and the model has never been validated
against any real-world ground truth.

---

## Factors

**Relevant factors.** The label rule engine (`synthetic._compute_risk_score`) weights
peat soil and wooden pile foundations most heavily, following KCAF-published domain
knowledge. Buildings constructed before 1945 on soft soil are disproportionately
represented in the `critical` class.

**Evaluation factors.** Per-class performance is reported below. No geographic breakdown
by province or municipality is included — training coordinates are synthetic, so a
geographic breakdown would measure the RNG's spatial distribution, not the model's
real-world generalisability. For a real-data model, performance by construction era
(pre-1945 / 1945–1970 / post-1970) and by province would be the most informative cuts.

## Evaluation data

**Dataset.** A held-out 20% test split of the same 10,000-row synthetic dataset used for
training. Training uses a three-way 60/20/20 split: 6,000 train, 2,000 val (early
stopping), 2,000 test. The test set is never used during training.

**Preprocessing.** Identical to training: categorical features are encoded against the
frozen vocabulary captured at training time (`TrainedModel.category_levels`).

**Limitations of the evaluation.**

- Test set shares the same generative process as the training set (same rule engine,
  same RNG priors). This is not independent validation.
- `neighborhood_damage_rate` is assigned per spatial hash bucket, so buildings in the
  same ~2 km cell share a feature value across the split — the reported accuracy is
  mildly optimistic as a result (see `docs/LIMITATIONS.md §L5`).
- A municipality-based grouped split (train: 2,283 real Gouda/Rotterdam/Zaanstad buildings;
  test: 974 real Dordrecht buildings from `real_data.parquet`) produced **9.2% accuracy**
  (macro F1 0.142) before BRO Bodemkaart integration. After integrating the BRO GeoPackage
  spatial join, accuracy improved to **61.4%** (macro F1 0.480). Root cause of the original
  collapse: `_classify_soil_by_coordinates` mislabelled Dordrecht as `sandy_clay` via the
  catch-all branch (bbox lon_max 4.72 misses the river-clay rule by 0.08 deg; bbox lat_max
  51.83 misses the peat-belt rule by 0.07 deg). Dordrecht is in reality a peat-and-river-clay
  city in the Drechtsteden. BRO integration resolved Consequence 1 (NaN encoding — `sandy_clay`
  now in vocabulary from Zaanstad) and partially resolved Consequence 2 (483/974 buildings now
  classified as `clay` from BRO; 491 still `sandy_clay` via coord-rule fallback for urban
  hardscape). The 0.614 figure is not a generalisation estimate; 8 of 11 features remain
  coordinate-based. See README Results and `docs/LIMITATIONS.md §L0` for full details.

## Training data

**Source.** Entirely synthetic, generated by `src/zakkend/data/synthetic.py` with
`RANDOM_STATE = 42`. 10,000 buildings with:

- Coordinates sampled within Netherlands bounding box (51.9°N–53.1°N, 4.1°E–6.9°E)
- `year_built` sampled uniformly from 1880–2023
- 8 features generated by domain-informed RNGs (InSAR rates from BodemDalingsKaart published
  means, groundwater norms from soil type, etc.); `soil_type` is hybrid (see Phase 2 pipeline)
- Labels assigned by `synthetic._compute_risk_score`: a deterministic weighted sum
  plus Gaussian noise, thresholded at three fixed cutoffs

**Feature provenance.**

| Feature | Source |
|---|---|
| `year_built` | ✅ PDOK BAG `bouwjaar` in Phase 2 pipeline; synthetic in training |
| `building_age` | ↳ Arithmetic derivative of `year_built` (`2026 − year_built`) |
| `foundation_type` | ❌ `rng.choice` weighted by construction era and soil type |
| `soil_type` | ⚠️ Hybrid: BRO Bodemkaart GeoPackage spatial join (29.5% of buildings, CC0) + coordinate-based rule fallback (70.5%; urban hardscape not mapped at 1:50 000) |
| `peat_thickness_m` | ❌ `rng` seeded by coordinates, TNO priors |
| `groundwater_depth_m` | ❌ `rng.normal` by soil type |
| `groundwater_variability` | ❌ `rng.beta` by soil type |
| `insar_deformation_mm_yr` | ❌ `rng.normal` seeded by coordinates, BodemDalingsKaart rates |
| `drought_exposure_index` | ❌ `rng` seeded by coordinates, KNMI latitude gradient |
| `distance_to_water_m` | ❌ `rng.exponential`, east/west split |
| `neighborhood_damage_rate` | ❌ `rng.beta` per spatial hash bucket |

**What the training data does not contain.** No real building damage records. No real
soil measurements. No real InSAR deformation observations. No real groundwater data. No
real foundation inspection records. The model has never seen a building that actually
experienced foundation damage.

## Quantitative analyses

**Per-class performance — random split** (2,000-row test set, sample-weighted training):

| Class | Precision | Recall | F1 | Support |
|---|---|---|---|---|
| `low` | 63.4% | 73.2% | **68.0%** | 142 |
| `moderate` | 88.1% | 84.2% | 86.1% | 989 |
| `high` | 74.7% | 79.8% | 77.1% | 535 |
| `critical` | 89.6% | 85.3% | 87.4% | 334 |
| **Overall** | — | — | **macro F1 0.797** | 2000 |

**Per-class performance — grouped split, after BRO integration** (Dordrecht holdout, 974 real PDOK BAG buildings):

| Class | Precision | Recall | F1 | Support |
|---|---|---|---|---|
| `low` | 7.7% | 13.6% | **9.8%** | 103 |
| `moderate` | 74.5% | 77.2% | **75.8%** | 640 |
| `high` | 66.7% | 36.6% | **47.2%** | 175 |
| `critical` | 81.2% | 46.4% | **59.1%** | 56 |
| **Overall** | — | — | **macro F1 0.480 · accuracy 0.614** | 974 |

**The before and after figures are not on the same test labels.** The rule engine derives labels
from `soil_type`; changing Dordrecht's soil classifications shifts the test-set class distribution:
`low` 177 → 103, `moderate` 632 → 640, `high` 128 → 175, `critical` 37 → 56. The 0.092 and
0.614 measure different classification problems.

**Before BRO integration: accuracy 0.092, macro F1 0.142 (below the 0.250 uniform baseline).**
Root cause: `_classify_soil_by_coordinates` assigned `sandy_clay` to every point in Dordrecht's
bbox via the catch-all branch — the bbox misses the river-clay rule by 0.08 deg longitude and the
peat-belt rule by 0.07 deg latitude. Dordrecht is in reality a peat-and-river-clay city in the
Drechtsteden; the `sandy_clay` label was a bbox placement artefact. Two consequences: (1) `sandy_clay`
absent from the frozen vocabulary — all 974 rows encoded as NaN; (2) rule engine assigned lower risk
to `sandy_clay` than `peat`, inverting the label distribution.

**After BRO integration:** the spatial join corrects 483/974 Dordrecht buildings to `clay`.
Dordrecht's soil is approximately 50% real (483 BRO-joined) and 50% coordinate-rule fallback
(491 urban-hardscape buildings). The 0.614 figure is computed on partially real soil.

**`low` class: 14 of 103 true-`low` buildings correctly identified; 183 total predicted as
`low` (precision 7.7%, recall 13.6%, F1 9.8%).** The headline macro F1 of 0.480 is carried
by `moderate` alone (F1 75.8%); the three remaining classes average F1 0.387. **Majority-class
reference point** (not a legitimate baseline — requires test labels): 640/974 Dordrecht buildings
are `moderate` = **0.657**. A constant `moderate` predictor would outperform the model's 0.614
on this test set.

See `docs/LIMITATIONS.md §L0` and README Results for full before/after details.

On the random split, sample weights improve `low` F1 from 0.603 → 0.680 (+7.7 pp)
with no meaningful loss on `moderate`.

**Intersectional analysis.** Not performed. The training data contains no demographic
variables. Geographic breakdown is not meaningful given the synthetic coordinates.

## Ethical considerations

**Property value effects.** A public risk score directly affects property values,
insurability, and mortgage terms. A homeowner labelled `critical` may face lower resale
value, higher insurance premiums, or reduced mortgage options — even if the label is
wrong. This effect is especially acute for lower-income owners who cannot afford the
structural inspection needed to contest the label.

**No demographic fairness analysis has been conducted.** No audit has been performed
for whether coordinate-derived features (e.g., `neighborhood_damage_rate`) serve as
proxies for postcode-level income or ethnicity.

**Disclosure requirement.** Any deployment that presents risk scores to property owners
should:

1. Disclose that the output is model-generated
2. Provide a clear path to contest the label (e.g., by commissioning a structural inspection)
3. Require human review of `critical` assessments before any consequential action

---

## Caveats and recommendations

1. **Do not use for any consequential decision.** The model has no real ground truth.
   No responsible use in property, insurance, or mortgage contexts is possible until
   validated against real damage data.

2. **Class probabilities are not calibrated.** `P(critical) = 0.85` is a relative
   confidence score, not a frequency estimate. Do not communicate probabilities to
   property owners as if they were calibrated frequencies.

3. **SHAP attributions reflect the rule engine, not real damage.** Feature contributions
   show what drives the synthetic label rule; they cannot be interpreted as causal
   explanations of actual foundation damage.

4. **The pipeline is structured for real-data integration.** BAG WFS is implemented;
   soil, InSAR, and climate sources are architected. The single highest-value next step
   is weak supervision from KCAF / municipal *funderingsrisico* zone data
   (see `docs/LIMITATIONS.md §L1`).
