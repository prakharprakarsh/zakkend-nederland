# 🏚️ Zakkend Nederland

> **ML-powered foundation subsidence risk assessment for Dutch homes.**
> An estimated **1 million Dutch homes** face foundation damage from soil subsidence,
> with total damage projected at **€60+ billion by 2050**. Homeowners currently have
> no way to know their risk until cracks appear. This project changes that.

## The problem

Peat soils shrink in drought. Wooden pile foundations rot when groundwater drops.
Together, these phenomena cause slow, irreversible foundation damage across the
western Netherlands — especially in cities built on reclaimed land (Gouda, Rotterdam-Zuid,
Zaanstad, Amsterdam-Noord, Dordrecht).

Key facts that make this a real problem worth solving:

- **1,000,000+** Dutch homes at risk (KCAF, TNO estimates)
- **€60B+** projected repair cost by 2050
- **Insurers do not cover** subsidence damage
- **Mortgage banks** (ING, Rabobank, ABN AMRO) are scrambling for risk models
- **Municipalities** need prioritization tools for funding schemes
- **Homeowners** have no accessible tool to check their own address

## Labels and metrics

There is no public per-address ground truth for Dutch foundation damage. The labels
used here — `low`, `moderate`, `high`, `critical` — are generated by an explicit,
documented rule engine in `synthetic._compute_risk_score`: a weighted sum of the 11
input features, plus a small noise term, thresholded at three fixed cutoffs.

This means the reported accuracy measures **rule-recovery** — how well XGBoost
reconstructs the rule engine's output — not real-world predictive skill. The ~17%
gap from perfect is driven by the noise term straddling the thresholds.

This is a legitimate use case: it proves the feature engineering pipeline and training
loop are wired correctly end-to-end. But it is a **pipeline integrity check**, not
evidence that the model can predict actual foundation damage. The next milestone
toward real predictive value is weak supervision from KCAF/municipal *funderingsrisico*
zone data; see `docs/LIMITATIONS.md`.

> The metrics in this README come from a **synthetic, 10,000-row training run**
> (60/20/20 split: 6,000 train / 2,000 val / 2,000 test), generated on the `hardening`
> branch. They do not reflect a real-data run.

## Data sources

Of the 11 model features, only `year_built` is measured directly from a government
registry (PDOK BAG `bouwjaar`). The building centroid (`lat`/`lon`) is also a real PDOK BAG
measurement — it drives the coordinate-based estimators for soil, InSAR, and drought — but
is not itself a model feature. `building_age` is derived arithmetically
(`2026 − year_built` in `pipeline._harmonize_to_schema`) and is not a separate
real measurement:

| Feature | Source |
|---------|--------|
| `year_built` | ✅ PDOK BAG `bouwjaar` (measured) |
| `building_age` | ↳ Arithmetic derivative of `year_built` (`2026 − year_built`) |
| `soil_type` | ⚠️ Hybrid: BRO Bodemkaart spatial join — PDOK GeoPackage CC0 (1,031 of 3,828 buildings = 26.9%; cached in `data/raw/bro_soil_cache.parquet`) + coordinate-based rule fallback (73.1%; urban hardscape not covered by the 1:50 000 rural map) |
| `peat_thickness_m` | ❌ `np.random.default_rng` seeded by coordinates, priors from TNO thickness ranges |
| `groundwater_depth_m` | ❌ `np.random.default_rng(42)`, draws from soil-type normal distributions |
| `groundwater_variability` | ❌ `np.random.default_rng(42)`, draws from soil-type beta distributions |
| `insar_deformation_mm_yr` | ❌ `np.random.default_rng` seeded by coordinates, mean values informed by BodemDalingsKaart published rates |
| `drought_exposure_index` | ❌ `np.random.default_rng` seeded by coordinates, latitude gradient from KNMI spatial maps |
| `distance_to_water_m` | ❌ `np.random.default_rng(42)`, exponential draw with east/west split |
| `neighborhood_damage_rate` | ❌ `np.random.default_rng(42)`, beta draw per spatial hash bucket |
| `foundation_type` | ❌ `np.random.default_rng(42)`, `rng.choice` weighted by construction era and soil type |

The domain priors used in the simulations (regional subsidence rates, soil-type
groundwater norms, foundation-era distributions) are informed by published Dutch
research. The problem is not that the estimators are arbitrary — it is that they
are estimators, not measurements. Calling them "real data" would be wrong.

## The ML approach

This project combines **three data modalities** to produce a per-address risk score:

| Modality | Source | Signal |
|----------|--------|--------|
| Satellite (InSAR) | Sentinel-1 / BodemDalingsKaart | Vertical ground deformation (mm/year) |
| Geospatial | PDOK BAG, TNO DINOloket | Building footprint, year, soil composition |
| Climate | KNMI | Precipitation deficit, drought indices |

**Model:** Gradient-boosted decision trees (XGBoost) with SHAP explainability for
every prediction — designed with **EU AI Act Article 13** transparency in mind;
see [`docs/EU_AI_ACT.md`](docs/EU_AI_ACT.md) for a full gap analysis.

## Quick start

```bash
# 1. Clone and enter
git clone https://github.com/prakharprakarsh/zakkend-nederland.git
cd zakkend-nederland

# 2. Create environment (Python 3.11 or 3.12)
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt -e ".[dev]"

# 3. Generate synthetic training data
python scripts/train.py

# 4. Launch the API
uvicorn zakkend.api.main:app --reload

# 5. Open the demo
open http://localhost:8000
```

The demo presents **11 numeric sliders** (construction year, soil type, foundation type,
groundwater depth, InSAR deformation rate, etc.). Adjust them and the model returns a
risk class, the four class probabilities, and a SHAP breakdown of the top drivers. The
Leaflet map visualises your click position but does not feed lat/lon into the model.

## Results

> **Read this first.** The two numbers below are not comparable evidence of the same thing.
> The random-split figure (0.824) measures rule-recovery on held-out rows from the same
> synthetic distribution. The held-out-city figure improved from **0.092 to 0.614** after
> BRO Bodemkaart soil integration corrected the root-cause mislabelling described below.
> Neither figure should be read as evidence of real-world predictive skill.

All figures generated by `python3 scripts/train.py` and
`python3 scripts/train.py --split grouped`, `RANDOM_STATE=42`, on the `hardening` branch.

### Random split — 0.824 accuracy (`python3 scripts/train.py`)

60/20/20 stratified split of the 10,000-row synthetic dataset (6,000 train / 2,000 val /
2,000 test). Early stopping on the val set (best iteration: 182). Labels are synthetic
(rule engine). **This number measures rule-recovery, not generalisation.**

**Per-class breakdown** (2,000-row test set, sample-weighted training):

| moderate | 88.1% | 84.2% | 86.1% | 989 |
| high | 74.7% | 79.8% | 77.1% | 535 |
| critical | 89.6% | 85.3% | 87.4% | 334 |

**Effect of sample weights** on minority class `low` (same split):

|-------|-----------------|---------------|-------|
| low | 0.603 | **0.680** | +0.077 |
| moderate | 0.865 | 0.861 | −0.004 |
| high | 0.749 | **0.771** | +0.022 |

### Held-out city — before BRO: 0.092 · after BRO: 0.614 (`python3 scripts/train.py --split grouped`)

Train: 2,283 real PDOK BAG buildings from Gouda + Rotterdam + Zaanstad (80/20 train/val split).
Test: 974 real PDOK BAG buildings from Dordrecht (`data/processed/real_data.parquet`).

**One root cause and two consequences — not three independent confounds.**

| Metric | Before BRO integration | After BRO integration |
|--------|------------------------|----------------------|
| XGBoost accuracy | 0.092 | **0.614** |
| Macro F1 | 0.142 | **0.480** |
| 4-class uniform random | 0.250 | 0.250 |
| `DummyClassifier(most_frequent)` | 0.058 | 0.058 |

> **The before and after figures are not on the same test labels.** The rule engine derives
> labels from `soil_type`; changing Dordrecht's soil classifications shifts the test-set class
> distribution: `low` 177 → 103, `moderate` 632 → 640, `high` 128 → 175, `critical` 37 → 56.
> The 0.092 and 0.614 measure different classification problems.

**Root cause — the coordinate classifier mislabels Dordrecht.** `_classify_soil_by_coordinates`
in `data/soil.py` assigns `sandy_clay` to every point in Dordrecht's bounding box via the
final catch-all `return "sandy_clay"`. Dordrecht is in reality a peat-and-river-clay city in
the Drechtsteden and one of the more subsidence-affected municipalities in the Netherlands; the
mislabelling is an artefact of where the bounding boxes were drawn. The bbox misses the
river-clay rule (requires `lon >= 4.8`; bbox lon_max is 4.72 — gap: **0.08 deg**) and the
peat-belt rule (requires `lat >= 51.9`; bbox lat_max is 51.83 — gap: **0.07 deg**).

Bounding-box coordinates and coordinate-rule soil assignments, from `config.TARGET_MUNICIPALITIES`,
verified by running `_classify_soil_by_coordinates` on all four corners and the centroid:

| Municipality | lon min | lat min | lon max | lat max | Coord-rule soil |
|---|---|---|---|---|---|
| Gouda | 4.68 | 52.00 | 4.75 | 52.03 | peat (all points) |
| Rotterdam | 4.40 | 51.88 | 4.56 | 51.96 | peat (lat ≥ 51.9) / sandy_clay (lat < 51.9) |
| Zaanstad | 4.75 | 52.43 | 4.88 | 52.50 | peat (all points) |
| Dordrecht | 4.62 | 51.78 | 4.72 | 51.83 | **sandy_clay — catch-all** (all points) |

**BRO Bodemkaart corrects 483 of 974 Dordrecht buildings to `clay`** (spatial join against the
PDOK GeoPackage; Zeekleigronden and Rivierkleigronden, consistent with Dordrecht's actual
Holocene peat/clay geology). The remaining 491 receive `sandy_clay` via the coordinate-rule
fallback — building centroids in urban hardscape and infrastructure zones not covered by the
1:50,000 rural soil map. **Dordrecht's soil labels are approximately 50% real (483 BRO-joined)
and 50% coordinate-rule (491 fallback); the 0.614 figure is computed on partially real soil.**

**Consequence 1 — NaN encoding [RESOLVED].** Before BRO, `soil_type = sandy_clay` was absent
from the frozen training vocabulary (all training cities peat-dominant), routing all 974 rows to
the XGBoost missing-value branch. After BRO, `sandy_clay` enters the vocabulary from Zaanstad
(167 buildings) and `clay` from 132 buildings across training cities; neither encodes as NaN.

**Consequence 2 — label distribution inversion [PARTIALLY RESOLVED].** The rule engine assigns
lower risk to `sandy_clay` than to `peat`. Before BRO, all 974 Dordrecht rows were `sandy_clay`,
producing 65% `moderate`/18% `low` labels — the inverse of the training distribution (76%
`critical`). After BRO, 483 buildings receive `clay` (higher risk than `sandy_clay`), shifting
the label distribution. The `low` class remains weakly predicted (F1 9.8%), reflecting residual
mismatch between the coord-rule `sandy_clay` labels for the 491 urban-hardscape buildings and
Dordrecht's actual clay-dominated geology.

**Per-class breakdown on Dordrecht (after BRO integration, real data):**

| Class | Precision | Recall | F1 | Support |
|-------|-----------|--------|----|---------|
| low | 7.7% | 13.6% | **9.8%** | 103 |
| moderate | 74.5% | 77.2% | **75.8%** | 640 |
| high | 66.7% | 36.6% | **47.2%** | 175 |
| critical | 81.2% | 46.4% | **59.1%** | 56 |

**Majority-class reference point** (not a legitimate baseline — it requires knowing the test-set
label distribution): 640 of 974 Dordrecht buildings are labelled `moderate` = **0.657**. A
constant `moderate` predictor would outperform the model's 0.614 on this test set. The model
adds no value over the majority class on this particular held-out city.

**`low` class: 14 of 103 true-`low` buildings correctly identified; 183 total buildings
predicted as `low` (precision 7.7%, recall 13.6%, F1 9.8%).** The headline macro F1 of 0.480
is carried almost entirely by `moderate` (F1 75.8%); the three remaining classes average
F1 0.387 (`low` 9.8%, `high` 47.2%, `critical` 59.1%).

**What the experiment now measures.** After BRO integration the grouped split is a partial
OOD test: soil type is now partially real (BRO for 49.6% of Dordrecht buildings), but the
remaining 8 features (InSAR deformation, groundwater depth/variability, drought exposure,
distance to water, neighbourhood damage rate, foundation type, peat thickness) are still
derived from coordinate-based estimators confounded with municipality geography. The 0.614
accuracy should not be read as evidence of real-world generalisation; it reflects improved
data quality for one of eleven features.

**The random-split figure (0.824) should not be read as evidence of generalisation.**
The 82.4% is achieved by recovering a synthetic rule engine on held-out rows from the same
distribution. The held-out-city result shows the limit of that rule-recovery when even one
feature's distribution (soil type) changes across cities.

## Model artefact format

The trained model is saved as two sibling files in `models/`:

- `subsidence_xgb.ubj` — XGBoost's portable UBJSON format, loadable across
  XGBoost versions without pickling
- `subsidence_xgb.meta.json` — feature schema, frozen categorical vocabulary,
  metrics, and the XGBoost version used at training time

**Why not joblib?** Joblib pickle deserialisation is arbitrary code execution — loading
a `.joblib` file you did not produce yourself is a supply-chain risk. The `.ubj` format
is XGBoost's own serialisation protocol; it is portable, version-stamped, and safe to
load from untrusted sources.

A full `requirements.lock.txt` (pinned from `pip freeze`) is committed alongside
`requirements.txt` so that the exact working environment is reproducible.

## Known limitations

See [`docs/LIMITATIONS.md`](docs/LIMITATIONS.md) for a full gap analysis. The key
points:

- **Labels are synthetic.** Accuracy measures rule-recovery, not predictive skill.
- **8 of 11 features are fully simulated** from domain-informed random number generators,
  not measured from instruments or registers. `soil_type` is hybrid (26.9% BRO Bodemkaart
  spatial join — 1,031 of 3,828 buildings; 73.1% coordinate rule).
- **No postcode lookup.** The UI accepts 11 manual numeric inputs; there is no
  geocoder.
- **No probability calibration.** The model outputs raw XGBoost softmax scores.
  `P(critical) = 0.85` does not mean 85% of such buildings will fail.
- **Class imbalance.** The `low` class is underrepresented and has the weakest F1
  (0.680 with sample weights; 0.603 unweighted — see Results).
- **Spatial leakage in the train/test split.** `neighborhood_damage_rate` is assigned
  per spatial hash bucket, so nearby buildings share a feature value across the split.
  The random-split figure (82.4%) overstates out-of-distribution performance as a result.
  The held-out-city evaluation improved from 0.092 to **0.614** (macro F1 0.480) after BRO
  Bodemkaart integration; see
  [`docs/LIMITATIONS.md §L0`](docs/LIMITATIONS.md#l0--grouped-split-accuracy-0092-before-bro--0614-after-bro-held-out-city-evaluation-is-not-a-valid-generalisation-test).
